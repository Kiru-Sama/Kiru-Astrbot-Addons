# 源码补丁说明（P1、P2、P4）

这四个补丁改的是 **AstrBot 自己的源码文件**（不是配置、不是插件）。
**AstrBot 一升级就会被覆盖，升级后要照这份重打一遍。**

## 怎么打

```powershell
# 进到 AstrBot 的包目录（下面这个路径按自己的安装位置改）
cd <AstrBot>\\.venv\\Lib\\site-packages\\astrbot

# 先干跑一遍，确认都能打上（--check 不会改文件）
git apply --check -p1 <.patch 所在目录>\\P1-cron_tools.py.patch
git apply --check -p1 <.patch 所在目录>\\P2-main.py.patch
git apply --check -p1 <.patch 所在目录>\\P4-astr_main_agent.py.patch

# 没问题再去掉 --check 真打
git apply -p1 <.patch 所在目录>\\P4-astr_main_agent.py.patch
```

> 没有 git 也行，用 `patch -p1 < xxx.patch`。
> **或者干脆照着下面每节的说明手改** —— 每个补丁都只有几行。
> 打完必须**重启 AstrBot**（改的是 .py 源码，配置那种热重载不适用）。

> 一行命令：
> ```powershell
> Get-FileHash <文件> -Algorithm SHA256 | % { $_.Hash.Substring(0,16).ToLower() }
> ```

## P1　定时任务参数兜底

- **文件**：`core/tools/cron_tools.py`
- **补丁**：`P1-cron_tools.py.patch`
- **改动量**：+8 / -0 行（13377 → 13935 字节）
- **校验值**：打之前 `fbf449014986f500` → 打之后 `6ad4e420b6cd2d2d`

**为什么改**

小模型（4B 级）调 future_task 时会漏传必填的 action 参数，于是它嘴上说'建好了'、实际什么都没建，日志里报 `action must be one of create, edit, delete, or list.`。补丁在 action 为空但给了 note/cron_expression/run_at 时按 create 处理。

## P2　戳一戳时按人设回应

- **文件**：`builtin_stars/astrbot/main.py`
- **补丁**：`P2-main.py.patch`
- **改动量**：+25 / -5 行（14105 → 15542 字节）
- **校验值**：打之前 `cd91bdc57194c2cf` → 打之后 `ea4f0b68b030ed32`

**为什么改**

别人戳（QQ 的戳一戳）机器人时，事件是「空文本 + 一个 Poke 组件」：唤醒路径要求 @ 或前缀（文本是空的），主动回复路径要求 Plain/Image/Json（Poke 不在列表里），两条都不通，所以毫无反应。补丁把「戳机器人自己」当成等价于「空 @」，并给它单独的提示词。

## P4　模型不支持工具时，不再往系统提示里塞工具提示

- **文件**：`core/astr_main_agent.py`
- **补丁**：`P4-astr_main_agent.py.patch`
- **改动量**：+11 / -1 行（70565 → 71178 字节）
- **校验值**：打之前 `1ebc3dd822a62383` → 打之后 `185173192800a368`

**为什么改**

原判据只看「有没有工具」，而 req.func_tool 非空是常态（人设未设工具、定时任务工具、SendMessageToUserTool 三条路都会喂饱它），跟模型能力无关。于是每轮都往人设末尾追加一段英文工具使用提示，纯 token 开销。补丁加上 `_provider_supports_modality(provider, 'tool_use')` 判据；modalities 为空列表视为「未配置」→ 保持原行为，不误伤老配置。
